## 0. The two gaps this closes (recap of RCA §5)

T4.37 (already on master) clears PCI bus-master on the **fault** path (a GSP-delivered `is_err_state`)
in three sites: `sleep()`, `on_device_hang()`, `device_fini()`. Two gaps remained, both root-caused to
**orphaned-session teardown**: a process exits with bus-master still enabled and its GSP-RM session not
cleanly unloaded; the server/DEXT then tears down that process's DMA mappings with zero quiescing
(RCA §1) while the still-running GSP-RM DMAs into them → `AppleT8110DART` `REQUIRE` → host panic.

- **A2 (fix 40-1):** `NVDev.__init__` raises *after* bus-master is enabled (any boot-time timeout) →
  the device is never registered (`device.py` never adds it) → `atexit`'s `finalize()`/`fini()` never
  runs for it → nothing ever clears MASTER → the half-open session stays armed until process exit.
  Panic 2's best-fit mechanism (RCA §4, panic 2 timeline).
- **A1 hole (fix 40-2):** `PCIIface.device_fini`'s T4.37 clear only fires `if self.dev_impl.is_err_state`.
  `is_err_state` is set *only* by a GSP-delivered fault event (`ip.py:73-74`). A wedge that never
  delivered one, but whose `fini()` unload RPC itself times out/raises (the "cmd 47" shape, seen live
  in T4.37 step A), exits with `is_err_state` False and MASTER on.

## 1. Fix 40-1 — `NVDev.__init__` (`tinygrad/runtime/support/nv/nvdev.py`)

### Seam analysis (verified from code, not assumed from the RCA's shorthand)

The RCA's phrasing ("wrap everything after the MASTER set... after that call returns") suggests the
seam is simply "wrap `_early_mmu_init()` through `init_hw()` in `__init__`, since `_early_ip_init()`
sets MASTER and `__init__` calls it first." **That reading is incomplete and was verified wrong before
writing any code:**

- MASTER is set unconditionally at `_early_ip_init`'s **nvdev.py:138** (was :127 pre-fix; renumbered by
  this diff) — but `_early_ip_init` does NOT return immediately after. It goes on (nvdev.py:139-146,
  post-fix numbering) to read `chip_id`/`chip_details`, dict-lookup `chip_name`/`fw_name` (a `KeyError`
  on any unrecognized chip is a real raise site), construct `NV_FLCN_COT`/`NV_FLCN` and `NV_GSP`, and
  finally call **`self.flcn.wait_for_reset()`** (nvdev.py:148, pre-fix :137) — which is
  `wait_cond(..., "waiting for reset")` (`support/nv/ip.py:94-96` / `:286-288`). `wait_cond` defaults to
  `timeout_ms=10000` and **raises on timeout** (`tinygrad/helpers.py:555`) — confirmed by reading the
  function signature directly. This is the exact same timeout-then-raise primitive the RCA calls "any
  boot-time RPC timeout," and it fires *inside* `_early_ip_init`, after MASTER is set, before that
  method returns to `__init__`.
- A try that only wraps `__init__`'s body *after* the call to `_early_ip_init()` would never see an
  exception raised by `wait_for_reset()` — it would already have escaped `_early_ip_init()` and propagated
  out of `__init__` uncaught. This is precisely the gap a `test_nv.py` test now proves (see §3).

**Chosen seam:** wrap the **entire body of `NVDev.__init__`** from immediately after the constructor's
first line (which must stay outside the try — see below) through the last `init_hw()` loop, in one
`try/except BaseException: <clear MASTER>; raise`. This covers both real raise points (inside
`_early_ip_init`, e.g. `wait_for_reset`; and after it returns, in `_early_mmu_init`/`init_sw`/`init_hw`)
with a single block, rather than two separate try/excepts split across methods.

Wrapping also incidentally covers `_early_ip_init`'s *own* pre-MASTER-set code (the `include()` calls,
the WPR2-conditional reset dance at nvdev.py:126-131). This is deliberately left in scope rather than
carved out: a failure there hits the same except-handler and clears a bit that's already 0 (or, in the
WPR2 branch, already cleared by that branch itself at nvdev.py:127) — `cmd & ~MASTER` on an already-clear
bit is a no-op, the same idempotency the T4.37 code already relies on (ops_nv.py's `sleep()` comment: "AND
with an already-clear bit is a no-op"). Splitting the try to start exactly at the MASTER-set line would
need restructuring `_early_ip_init` into two methods for no behavioral gain, for a larger and riskier diff.

`self.pci_dev, self.devfmt, self.mmio = pci_dev, pci_dev.pcibus, pci_dev.map_bar(0, fmt='I')`
(nvdev.py:92) stays **outside** the try: if `pci_dev.map_bar(...)` itself raises, none of that tuple
assignment happens yet (Python evaluates the whole RHS before any assignment), so `self.pci_dev` would
not exist for the handler to use — and MASTER is not part of this device's init flow yet at that point
regardless (it's set later, inside `_early_ip_init`).

### The fix (nvdev.py:94-113)

```python
    self.smi_dev, self.is_booting, self.is_err_state = False, True, False
    try:
      self._early_ip_init()
      self._early_mmu_init()

      # No booting state, gsp client is reinited every run.
      self.is_booting = False

      for ip in [self.flcn, self.gsp]: ip.init_sw()
      for ip in [self.flcn, self.gsp]: ip.init_hw()
    except BaseException:
      self.pci_dev.write_config_flush(pci.PCI_COMMAND, self.pci_dev.read_config(pci.PCI_COMMAND, 2) & ~pci.PCI_COMMAND_MASTER, 2)
      raise
```

`pci`/`pci.PCI_COMMAND_MASTER` were already imported (nvdev.py:4) — no new import.

## 2. Fix 40-2 — `PCIIface.device_fini` (`tinygrad/runtime/ops_nv.py:615-629`)

T4.37 already wraps `self.dev_impl.fini()` in `try/finally`, so the `is_err_state` check always runs
even if `fini()` raises — but the check itself is still gated on `is_err_state`, which a raising-without-
a-fault-event wedge never sets. Fix: add an `except BaseException` between the existing `try` and
`finally` that clears unconditionally on any raise, then re-raises; the original `finally`'s
`is_err_state` clear is left completely unchanged (still needed for the case where `fini()` *succeeds*
RPC-wise but the device is already marked faulted).

```python
    try: self.dev_impl.fini()
    except BaseException:
      self.pci_dev.write_config_flush(pci.PCI_COMMAND, self.pci_dev.read_config(pci.PCI_COMMAND, 2) & ~pci.PCI_COMMAND_MASTER, 2)
      raise
    finally:
      if self.dev_impl.is_err_state:
        self.pci_dev.write_config_flush(pci.PCI_COMMAND, self.pci_dev.read_config(pci.PCI_COMMAND, 2) & ~pci.PCI_COMMAND_MASTER, 2)
```

All four `(fini raises?, is_err_state?)` combinations were traced by hand:
- succeeds / False → neither branch fires → untouched (healthy path, the #16536 guard).
- succeeds / True → `finally` clears (unchanged from T4.37).
- raises / True → `except` clears + re-raises; `finally` still runs before the exception propagates
  further and clears again — redundant but idempotent, so harmless (same idiom already used in `sleep()`).
- raises / False → `except` clears + re-raises; `finally`'s condition is False so no second write. This
  is the case that was broken pre-fix (A1 hole) and is now covered.

A single write per teardown (skipping the redundant write in the third case) was considered and
rejected as unnecessary complexity for a register write that's already established elsewhere in this
file as idempotent and cheap — kept the diff to exactly what the RCA specified (one `except` clause).

## 3. Tests (`test/unit/test_nv.py`)

`_FakePCIConfig` (T4.37's existing fake config-space object) gained two attributes so it can also drive
the real `NVDev.__init__` end-to-end: `self.pcibus` (a placeholder string) and `map_bar(self, *a, **k):
return None`. Purely additive — nothing pre-existing reads either, so no existing test's behavior changes.

**New class `TestNVQuiesceOnInitFailure`** (40-1), 3 tests. Drives the *real* `NVDev.__init__` (called
unbound against a `SimpleNamespace`, exactly T4.37's `PCIIface.device_fini(fake)` style) with
`_early_ip_init`/`_early_mmu_init`/`flcn`/`gsp` stubbed as plain callables (no hardware):
- `test_init_clears_bus_master_when_early_ip_init_raises_after_master_set` — stub sets MASTER then
  raises, *before* `_early_ip_init()` returns. This is the test that would fail under the RCA's naive
  "wrap only after `_early_ip_init()` returns" reading, proving the wider seam is necessary.
- `test_init_clears_bus_master_when_a_later_boot_step_raises` — `_early_ip_init` stub succeeds,
  `gsp.init_hw()` raises (the other seam, and the RCA's "confirmed real trigger" phase).
- `test_init_leaves_bus_master_set_when_boot_succeeds` — **negative control**: fully healthy stubbed
  boot must leave MASTER set and must not raise; also asserts `is_booting is False` to confirm the
  healthy path still runs to completion (not silently altered by the new except).

**`TestNVQuiesceOnFault`** (existing class, 40-2) gained one test,
`test_device_fini_clears_bus_master_when_fini_raises_without_err_state`: `fini()` raises `TimeoutError`
with `is_err_state=False` → asserts MASTER cleared and the exception still propagates. The existing
`test_device_fini_leaves_bus_master_when_clean` (fini succeeds, `is_err_state=False` → MASTER untouched)
already serves as 40-2's **negative control** (the #16536 guard) and needed no changes — it was re-run
to confirm it still passes post-fix (it does; see §5).
