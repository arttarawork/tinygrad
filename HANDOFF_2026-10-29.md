## 3. Things that bit (read before touching kernels or memory)

- **Card memory at 262k was the binding constraint until T4.128.** TinyJit's first call (`cnt=0`) runs the forward eagerly, and an
  eager schedule cannot plan buffers custom kernels write into (`Tensor.empty` outputs are "held", schedule/__init__.py:218): every
  block's partials and q8 activations were alive at once — on 0c6178834 within ~50 MB of OOM (`scripts/alloc_log.py`). Fix: non-spec
  prefill jit families capture on their FIRST call with `prune=True` (one-time KV zero-fill runs once) → warm-up peak 21.27 GB.
  Dead ends, both on record: per-block realize in the eager pass gave WRONG chunked-prefill results
  (`test_chunked_matches_one_token_prefill`), and per-block realize during capture blew the arenas 315 MB → 3.5 GB. Spec (MTP)
  families keep the eager first call (captured-first they differ from eager by fp16 ulps). T4.126 also needed the per-step q8
  caches cleared after each forward (`Transformer._forward_step`).
- **The standing prefill attention kernel (T4.113, live 09-16 → 10-29) mis-weighed its chunk slots.** It scales scores by log2(e)/√D and stored
  its exp2-domain running max, but `_merge_partials` expects the natural-domain max the decode/T4.107b kernels store — slots below the row
  max got weight w^1.44 instead of w, so attention over prompts longer than one chunk was too local. Found by the T4.130 agent on the
  emulator; no gate could see it (refs and candidates both had it; the 09-16 gate was 1–3 slots deep). Fix: `/ LOG2E` in the stats store.
  Lesson: a new kernel's gate must include a reference that does NOT share its merge/epilogue; long-context gates run against the
  T4.107b kernel (`REF_ENV="NV_ATTN_WMMA=0"` in `t4122_gate.sh`).
- **Codegen drops a store gate it can pin (T4.129 agent):** in the RESHAPE index flattening, `gated_given_valid` substitutes what a gate
  pins (e.g. `2t+1 < 2` ⇒ t = 0) into the gated component, then `drop_and_clauses` removes every gate clause whose ranges no longer
  appear — the store becomes unconditional (`eq` gates survive because `parse_valid` never parses CMPEQ). Gate a component that
  carries the lane (dim/column), or use `eq`; `test_out_store_gates_survive_small_g` is the regression test.
- **`PROFILE=1` + many schedules exhausts TinyGPU host-memory mappings** (no unmap verb, T4.18): measure wall time with `PROFILE=0`.
- **tinygrad bug found by the T4.128 agent (not fixed upstream here):** a loop index written `step % 2` makes the range-splitting
  pass split the loop, and `add_war_barrier` doesn't recognise the split ranges — the end-of-step `__syncthreads()` silently
  disappears (a race). Workaround `& 1`; tests pin the barriers. Any split loop using local memory is exposed.
- **`pooled-serve.sh` forces `GDN_CHUNK=32`**, and generate() caps the chunk at it: `PREFILL_CHUNK` alone does nothing.
- **The server's `gen:` figure** included the post-prefill snapshot store until T4.125c; there is no ~5 ms "server overhead".
- **Fused norm kernel:** `add_rmsnorm_q8_nv` costs 13.5 µs × 129 per token whatever its thread count (`scripts/norm_bench.py`): a fixed
  launch + single-block latency cost; parked.
- **The `cmd | tail && git commit` trap** merged two mypy failures (exit code of tail); gate on `cmd > out; rc=$?`.
- Agents work CPU/NULL/PYTHON-emulator only (kernels are run bit-exact on tinygrad's PYTHON device); the orchestrator does every card
  run, gate, lint and merge. Opus 5.5 for kernel design (Fable unavailable since 10-28), Sonnet for tight specs, ≤ 2 heavy at once.
