## 3. Things that bit (read before touching kernels or memory)

- **Card memory at 262k is the binding constraint.** The first prefill call (TinyJit's eager pass, `cnt=0`) runs the whole forward
  as one unplanned schedule: every block's temporaries are alive at once (16 × 50 MB prefill-attention partials at 128 tokens). On
  0c6178834 that peak is within ~50 MB of OOM (`scripts/alloc_log.py`). T4.126 OOMed until the per-step q8 caches were cleared after
  each forward (`Transformer._forward_step`); T4.128 OOMed until the eager pass realized block by block (`not capturing` only —
  doing it during capture blew the planned arenas from 315 MB to 3.5 GB).
- **`PROFILE=1` + many schedules exhausts TinyGPU host-memory mappings** (no unmap verb, T4.18): measure wall time with `PROFILE=0`.
- **tinygrad bug found by the T4.128 agent (not fixed upstream here):** a loop index written `step % 2` makes the range-splitting
  pass split the loop, and `add_war_barrier` doesn't recognise the split ranges — the end-of-step `__syncthreads()` silently
  disappears (a race). Workaround `& 1`; tests pin the barriers. Any split loop using local memory is exposed.
- **`pooled-serve.sh` forces `GDN_CHUNK=32`**, and generate() caps the chunk at it: `PREFILL_CHUNK` alone does nothing.
- **The server's `gen:` figure** included the post-prefill snapshot store until T4.125c; there is no ~5 ms "server overhead".
- **Fused norm kernel:** `add_rmsnorm_q8_nv` costs 13.5 µs × 129 per token whatever its thread count (`scripts/norm_bench.py`): a fixed
  launch + single-block latency cost; parked.
- **The `cmd | tail && git commit` trap** merged two mypy failures (exit code of tail); gate on `cmd > out; rc=$?`.
- Agents work CPU/NULL/PYTHON-emulator only (kernels are run bit-exact on tinygrad's PYTHON device); the orchestrator does every card
  run, gate, lint and merge. Opus 5.5 for kernel design (Fable unavailable since 10-28), Sonnet for tight specs, ≤ 2 heavy at once.
